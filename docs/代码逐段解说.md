## 阅读前先补几种 Python 语法

读不懂一行代码时，先问：右边算出了什么？左边名字指向什么？后面哪里又用到了它？

| 写法 | 直观理解 | 例子 |
| --- | --- | --- |
| `a = expression` | 先计算右边，再给结果起名 | `n = 2+3` 后 n 为 5 |
| `object.name` | 访问对象的属性或方法 | `self.seed` 取设置；`rng.uniform(...)` 调用操作 |
| `function(...)` | 用括号里的材料执行操作，接收返回值 | `make_pose(...)` 返回动作数组 |
| `items[0]` | 按零起始编号取元素 | 第一个元素编号是 0 |
| `sample["pose"]` | 按字典字段名取内容 | 取出一个样本包里的动作 |
| `return a,b` | 打包两个结果交还调用者 | `x,y = function()` 按顺序接收 |
| `self.layer = ...` | 在当前对象里保存层或其他内容 | 其他方法能继续访问它 |

变量名像贴在对象上的标签：rng 指向生成器对象，model 指向网络对象，pose 通常指向数组或张量，loss 指向标量张量。不能看到 `=` 就以为左边必然是一个普通数字。

本文每节先保留原代码和概述，再用五级小标题补充直观讲解。实际执行的输出会标明环境；便于手算的假设例子会明确说明，不代表模型真的训练出了那些参数。

### 数组、张量和 shape：数字放在什么样的容器里？

标量 `2` 是一个数，形状记为 `[]`；`[2]` 是装了一个数的一维容器，形状 `[1]`；`[[2]]` 是一行一列的二维容器，形状 `[1,1]`。数量相同，接口含义却不同。

本项目先用 NumPy 数组制作答案，再用 PyTorch 张量交给模型。张量可以放在 CPU/GPU，并在需要时记录求导过程，但并不是所有张量都会自动求导，例如类别整数和 mask 通常不需要。

把 `[B,24,5,2]` 想成 B 本翻页书，每本 24 页，每页有 5 个点，每点记录 x、y 两个数：

```text
pose[样本号,帧号,关节号,坐标号]
pose[0,2,1,0] → 第1个样本、第3帧、第2点的 x
```

以下常见操作改变的是容器组织方式，未必改变数值：

- `unsqueeze`：加一个长度为 1 的轴，像给一份材料套一个批次盒子。
- `reshape`：在元素总数不变时换一种排版，像把长行折成多页表。
- `transpose`：交换两根轴，像交换行列对应的含义。
- `cat`：拼接多份数据，元素总数增加；与前面三个操作不同。
- 广播：长度为 1 的轴可在运算时与另一个张量匹配，像一帧的开关同时控制该帧所有坐标；不是任意两个形状都能运算。

不必背住全部规则，先检查每条轴代表什么，再核对形状。文中用 B=1、2 或更短序列举例时，会说明是实际配置还是手算缩小版。

## 第一章：先理解数据

这个文件决定“题目”和“标准答案”如何产生。这里只模拟一条含 5 个点的二维关节链，并没有读取真实手语数据。

- `math` 计算三角函数；NumPy 生成坐标和随机数；PyTorch 把数据交给网络；`Dataset` 定义数据集接口。
- `GLOSS_NAMES` 给类别编号命名：0 抬手、1 挥手、2 指向。`NUM_GLOSSES=3` 是类别数。
- `NUM_FRAMES=24` 是每段动作的帧数，`NUM_JOINTS=5` 是每帧的关节数，`POSE_DIM=10` 是每帧的坐标数。
- 一个 `pose` 的形状是 `[24,5,2]`。`pose[t,j,0]` 是第 t 帧第 j 个点的 x 坐标，最后一维的 1 对应 y。

### 导入与文件级定义

### `ToySignDataset`

`class ... (Dataset)` 表示继承 PyTorch 数据集接口。三个方法分别负责保存配置、报告长度、按编号生成一个样本。数据没有预先全部存到内存；DataLoader 取某个编号时才生成它。

#### `__init__`

原文件：`src/data.py`，第 15 行起。

```python
def __init__(self, size=1024, seed=0):
    self.size = size
    self.seed = seed
```

`self` 代表当前数据集对象。`size` 是样本总数，`seed` 是随机种子的起点。默认参数只在调用者没有显式传值时使用；这里不创建神经网络，也不生成全部样本。

##### 用“按编号制作练习题的工厂”理解对象

执行 `dataset = ToySignDataset(size=8, seed=7)` 时，右侧创建一个数据集对象，左侧名字 `dataset` 指向这个对象。可以把对象理解为一个带有设置和操作按钮的工厂：

```text
dataset 这个名字 → 数据集对象
                    ├─ size = 8：能提供 8 道题
                    ├─ seed = 7：出题规则的起始编号
                    ├─ __len__：查询题目数量
                    └─ __getitem__：按题号制作一道题
```

调用时，Python 自动把当前对象传给 `self`，所以 `self.size = size` 是“把收到的 8 存在当前对象的 size 属性里”。`self` 不是什么神经网络张量，只是方法访问当前对象的入口。

`size` 是本次函数调用中的局部变量；`self.size` 是对象里保存的属性，构造函数结束后仍能通过 `dataset.size` 读取。类似把电话里听到的数字写进随身记事本，之后就不需要重新打电话。

这时没有生成 8 段动作，只有工厂设置完成。真正取 `dataset[0]` 时才调用后面的 `__getitem__`。若另建 `other = ToySignDataset(size=3, seed=100)`，它有自己的设置，不会改写 dataset。

原文件：`src/data.py`，第 19 行起。


返回样本总数，让 `len(dataset)` 和 DataLoader 知道可以读取多少个编号。

##### 一个实际调用

```python
dataset = ToySignDataset(size=8, seed=7)
print(len(dataset))  # 8
```

`len(dataset)` 会使用 `__len__`。方法把保存的整数 8 返回给调用者，像工厂告知“共有 8 个题号”，并不会制作或检查每一道题。常规索引范围是 0 到 7；但当前 `__getitem__` 本身没有边界检查，不能据此认为手动访问编号 8 一定会自动报错。DataLoader 的默认采样机制会按长度选择有效编号。

#### `__getitem__`

原文件：`src/data.py`，第 22 行起。

```python
def __getitem__(self, index):
    rng = np.random.default_rng(self.seed + index)
    gloss = int(rng.integers(0, NUM_GLOSSES))
    side = float(rng.choice([-1.0, 1.0]))
    scale = float(rng.uniform(0.85, 1.15))
    root_shift = float(rng.uniform(-0.06, 0.06))
    speed = float(rng.uniform(0.8, 1.25))
    pose = make_pose(gloss, side, scale, root_shift, speed)
    extra = np.array(
        [side, (scale - 1.0) / 0.15, root_shift / 0.06],
        dtype=np.float32,
    )
    return {
        "gloss": torch.tensor(gloss, dtype=torch.long),
        "extra": torch.from_numpy(extra),
        "pose": torch.from_numpy(pose),
    }
```

1. `default_rng(self.seed + index)` 为每个编号建立固定的随机数发生器。同一个数据集的同一编号每次得到相同结果；打乱读取顺序不会改变该样本。
2. `gloss` 在 0、1、2 中选择；`side` 取 -1 或 1，控制水平方向；`scale` 控制四段骨骼的长度；`root_shift` 控制根节点水平位置；`speed` 改变动作的时间进程。
3. `make_pose(...)` 根据这些参数生成标准答案，而非模型预测。
4. `extra` 把方向、尺度、位移放进长度为 3 的数组。后两项经过缩放，落在约 [-1,1] 内，避免三个条件的数值范围差得太多。`speed` 没有放入条件。
5. 返回字典：`gloss` 是 `long` 类型的标量张量，`extra` 为 `[3]`，`pose` 为 `[24,5,2]`，后两者是 float32。`from_numpy` 在这里与数组共享内存；样本生成后不再改动数组。

DataLoader 会把多个字典按同名字段堆叠，B 个样本变为 `gloss:[B]`、`extra:[B,3]`、`pose:[B,24,5,2]`。

##### 先把第一行拆到不能再拆：rng 到底是什么？

```python
rng = np.random.default_rng(self.seed + index)
```

Python 的 `=` 表示赋值：**先计算右边，再让左边的名字指向计算结果**。不是数学里的等式，也不是左右同时计算。

| 片段 | 在这行中的实际含义 |
| --- | --- |
| `self.seed` | 当前数据集保存的起始种子，例如 7 |
| `index` | 当前要读取的样本编号，例如 0 |
| `self.seed + index` | 这道题的种子，此时为 7 |
| `np` | 前面 `import numpy as np` 给 NumPy 起的简称 |
| `np.random` | NumPy 中提供随机数功能的模块 |
| `default_rng(7)` | 用种子 7 创建一个随机数生成器对象 |
| `rng` | 给这个对象起的局部变量名，常用作 random number generator 的缩写 |

**rng 不是随机产生的一个数字，而是一个能不断产生数字的对象。**它的类型是 NumPy 的 `Generator`。你也可以把变量名改为 `random_machine`，只要后面一致修改，意思相同。

##### 比喻：一台有内部进度的抽签机

把 `rng` 想成一台抽签机，`seed` 是初始化机器的设置编号。相同设置、相同抽签操作顺序，会产生可重复的结果。

```text
种子 7 → 创建抽签机 rng
              ├─ integers(...)：抽一个整数
              ├─ choice(...)：从候选列表抽一个选项
              └─ uniform(...)：从给定区间抽一个小数
```

`rng.integers(...)` 中的点表示“使用 rng 对象提供的 integers 方法”。后面的括号提供这次抽签的规则，方法调用的结果才是数字。

每调用一次，抽签机的内部状态会向前推进。**固定种子不意味着每次调用都返回同一个数；重新按相同种子创建机器，才会从相同起点重演。**这些是伪随机数，不是每次从物理噪声重新取数。

##### 按当前代码顺序运行一遍：seed=7、index=0

下面数值在本机 NumPy 2.4.6 环境实测，展示时进行了四舍五入；不要把具体小数当成跨版本永远不变的接口保证。

| 代码执行到哪里 | 得到什么 | 如何使用 |
| --- | --- | --- |
| `rng = default_rng(7)` | 一个 Generator 对象 | 后面五行用同一台抽签机 |
| `gloss = int(rng.integers(0, 3))` | `2` | 选择“指向”动作；上界 3 不包含在内 |
| `side = float(rng.choice([-1.0, 1.0]))` | `1.0` | 骨骼向 x 增大方向延伸 |
| `scale = float(rng.uniform(0.85, 1.15))` | `1.119164` | 骨骼比基础长度约长 11.9% |
| `root_shift = float(rng.uniform(-0.06, 0.06))` | `0.033082` | 根节点向右偏移约 0.033 |
| `speed = float(rng.uniform(0.8, 1.25))` | `0.901343` | 改变时间到动作进度的映射 |

`int(...)` 与 `float(...)` 把生成器返回的 NumPy 数值转换为普通 Python 整数、小数；它们不再额外抽签。这里 gloss=2 的指向姿态本身是静止的，所以这次抽到的 speed 不会改变最终动作。

可以亲手验证抽签机的“推进”和“重置”：

```python
import numpy as np

rng = np.random.default_rng(7)
first = rng.integers(0, 3)   # 第一次调用，从当前状态抽取
second = rng.integers(0, 3)  # 第二次调用，内部状态已推进

restarted = np.random.default_rng(7)
again = restarted.integers(0, 3)
print(first, second, again)
assert first == again
```

连续两次结果可能碰巧相同，不能据此认为内部状态没动。这个小片段第二次调用的是 integers，而原函数第二次调用的是 choice，**两者不是同一段抽样操作，不能逐项套用上表后续结果**。如果在原函数中插入新的随机调用，也可能改变后面抽出的数据。

##### 为什么使用 seed + index，而不是一直复用一台机器？

假设 `dataset.seed=7`：

```text
dataset[0] → 临时创建种子 7 的机器 → 按固定顺序制作第 0 题
dataset[1] → 临时创建种子 8 的机器 → 按固定顺序制作第 1 题
dataset[0] → 再创建种子 7 的机器   → 重演第 0 题
```

DataLoader 可以先读 1 再读 0，只改变出题顺序；第 0 题自身仍按种子 7 生成。`rng` 是这个方法内部的局部名字，每次调用都会重新创建对象；它没有保存成 `self.rng`，也不会在不同样本间继续接着抽。

不同种子通常会带来不同样本，但不能保证每个字段都不同，更不保证每个编号都是独一无二的动作。例如多个样本完全可以抽到同一个 gloss。

##### pose 和 extra：一个是答案，一个是部分出题条件

此时 `make_pose(...)` 类似按照抽到的配方制作标准答案。返回的 pose 有 24 张“关节坐标表”，每张表 5 行、2 列。上述样本首帧的前两个点约为：

```text
根节点：   [0.533082, 0.780000]
第 1 个点：[0.754402, 0.746551]
```

`pose` 是局部变量名，里面指向 NumPy 数组；这行没有调用神经网络，也没有进行训练。

`extra` 则保存供某些实验使用的条件：

```text
side                            = 1.0
(scale - 1.0) / 0.15             ≈ 0.794428
root_shift / 0.06                ≈ 0.551371
extra                           ≈ [1.0, 0.794428, 0.551371]
```

例如尺度为 1.0 时归一化为 0，1.15 时为 1，0.85 时为 -1。它像把不同单位的刻度尺改成相近范围，方便网络处理；并没有把实际骨长都改成 1。

`np.array([...], dtype=np.float32)` 将三项装进一个数值数组。`[]` 是列表语法，逗号分开元素；`dtype` 指定每个数用 32 位浮点数保存。float32 可能带来微小舍入，并不表示只保留 32 位小数。

##### return 字典：给调用者一个带字段名的样本包

`return` 把结果交还给调用者并结束本次函数。字符串键 `"gloss"`、`"extra"`、`"pose"` 像三个标签，让后续代码知道从哪里取什么。

```text
sample = dataset[0]
sample["gloss"] → tensor(2)，一个标量，形状 []
sample["extra"] → 三个条件数，形状 [3]
sample["pose"]  → 一段动作，形状 [24,5,2]
```

`torch.tensor` 根据 gloss 创建整数张量；`torch.from_numpy` 给 NumPy 数组建立共享底层数据的张量视图。可以想成同一份数字通过两种工具访问，不是复制一张完全独立的表。本代码之后不再改这些数组。

返回的样本包里没有 rng：它的任务已完成。baseline 也不会因为字典里有 extra 就自动使用 extra，是否使用由后面的 build_condition 决定。

##### DataLoader 如何把样本包组成批次？

取 B=2 的简化例子，假设第二个样本类别为 0：

```text
第 0 包：gloss=2，extra=[a,b,c]，pose=一段24帧动作
第 1 包：gloss=0，extra=[d,e,f]，pose=另一段24帧动作
                         ↓ 按同名字段堆叠
batch["gloss"] = [2,0]                 形状 [2]
batch["extra"] = [[a,b,c],[d,e,f]]      形状 [2,3]
batch["pose"]  = 两段动作摞在一起        形状 [2,24,5,2]
```

这里第二个样本及字母是教学示意，不是上面种子 8 的实测输出。DataLoader 没把 24 帧打乱；shuffle 打乱的是样本编号。

#### `make_pose`

原文件：`src/data.py`，第 41 行起。

```python
def make_pose(gloss, side=1.0, scale=1.0, root_shift=0.0, speed=1.0):
    frames = np.linspace(0.0, 1.0, NUM_FRAMES, dtype=np.float32)
    phases = np.power(frames, speed)
    lengths = np.array([0.20, 0.18, 0.12, 0.10], dtype=np.float32) * scale
    poses = np.zeros((NUM_FRAMES, NUM_JOINTS, 2), dtype=np.float32)

    for frame_index, phase in enumerate(phases):
        if gloss == 0:
            angles = [0.65 - 1.8 * phase, 0.10, 0.08, 0.05]
        elif gloss == 1:
            angles = [
                -0.35,
                0.25,
                0.25 + 0.65 * math.sin(2.0 * math.pi * 2.0 * phase),
                0.10,
            ]
        else:
            angles = [-0.15, -0.10, -0.05, -0.10]

        x, y = 0.50 + root_shift, 0.78
        poses[frame_index, 0] = (x, y)
        for joint_index, (length, angle) in enumerate(zip(lengths, angles), start=1):
            x += side * float(length) * math.cos(angle)
            y += float(length) * math.sin(angle)
            poses[frame_index, joint_index] = (x, y)
    return poses
```

1. `linspace` 把动作时间均匀采成 24 个点。`frames ** speed` 将时间变为动作进度：speed > 1 时中途进度偏小、后段追上；speed < 1 则相反。它是时间扭曲，不是增加帧数或简单的恒速倍率。
2. 四段长度乘 `scale`。5 个关节之间恰好有 4 条骨骼。`zeros` 预留 `[24,5,2]` 的输出。
3. 外层循环逐帧选择四段骨骼的角度。抬手让第一段角度随进度变化；挥手用正弦函数让第三段来回摆动，归一化进度内有两个周期；指向的角度不随时间变，因而是静止姿态。
4. 每帧从 `(0.50+root_shift,0.78)` 出发。`poses[frame_index,0]` 保存根节点。
5. `zip(lengths,angles)` 配对长度和角度，`enumerate(...,start=1)` 生成其余关节编号。每段位移为 `(side × length × cos(angle), length × sin(angle))`，叠加在上一个关节上。角度单位为弧度，且是相对全局坐标轴的角度，并未累加父骨骼角度。
6. 返回全部帧。绘图会反转 y 轴，所以 y 越小画面位置越高。坐标并未裁剪到 [0,1]；部分姿态可能被固定绘图范围截掉。

##### 把动作想成一本有 24 页的小翻页书

`frames` 像给书页标上从 0 到 1 的时间标签：`[0,1/23,2/23,...,1]`，共 24 项。`phases` 是每页实际走到的动作进度，`poses` 是还未填入坐标的整本书。

为了手算，以下采用简单参数：`gloss=0, side=1, scale=1, root_shift=0, speed=1`，并非上节的随机样本。

1. 第一页时间为 0，进度 `0**1=0`，第一段角度 `0.65-1.8×0=0.65`。
2. 根节点先写为 `(0.50,0.78)`。
3. 第一段长 0.20，位移约为 `(0.20cos(0.65),0.20sin(0.65))=(0.159217,0.121037)`。
4. 所以第一个非根关节约为 `(0.659217,0.901037)`，写进 `poses[0,1]`。
5. 第二段长 0.18、角度 0.10，接着在这个点上加位移，而不是重新从根节点出发。

最后一页进度 1，第一段角度变为 -1.15，第一非根关节约为 `(0.581697,0.597447)`。因为绘图 y 轴朝下，y 变小就是抬高。

`x += ...` 等价于 `x = x + ...`，像沿骨骼链走一步后更新自己所在位置。下一段从新位置继续出发。`poses[frame_index,joint_index] = (x,y)` 则是把当前位置记入表格，和更新 x、y 的工作不同。

`enumerate(phases)` 每次给出 `(页号,进度)`；内层 `enumerate(zip(lengths,angles),start=1)` 每次给出 `(关节号,(骨长,角度))`。括号中的多个名字是解包，不是额外函数：例如一项 `(1,(0.20,0.65))` 会分别赋给 joint_index、length、angle。

`speed` 的名字容易误导：在假想时间 0.5，speed=2 会让进度成为 0.25，speed=0.5 会让进度约为 0.707。它改变中途进度，但两端仍是 0 和 1；24 帧采样中不一定恰好有时间 0.5，这里用它便于手算。

挥手分支的 sin 让第三段角度周期变化，其他段不是跟着一起做同样的摆动；else 分支一直使用固定角度。函数默认所有非 0、1 的 gloss 都进入 else，数据集只会提供合法的 2。

#### `make_gloss_one_hot`

原文件：`src/data.py`，第 69 行起。

```python
def make_gloss_one_hot(gloss):
    return torch.nn.functional.one_hot(gloss, num_classes=NUM_GLOSSES).float()
```

把类别编号改成 one-hot，例如 `[0,2] → [[1,0,0],[0,0,1]]`。不直接把 0、1、2 当连续数值，可避免暗示类别之间存在大小和距离关系。`.float()` 转为线性层通常使用的浮点类型。批量输入 `[B]` 变为 `[B,3]`。

##### 类别编号变成三个指示灯

假设一批两个样本，类别是 `[2,0]`。三个灯依次代表“抬手、挥手、指向”：

```text
2 → [0,0,1] → 只点亮“指向”灯
0 → [1,0,0] → 只点亮“抬手”灯
```

函数输出相应的二维张量 `[[0.,0.,1.],[1.,0.,0.]]`。这些不是模型预测的概率，而是确定的输入编码。`.float()` 像把整数刻度改用小数格式表示，灯的位置没有变化。

单个标量类别输入会输出形状 `[3]`；经过 DataLoader 的 `[B]` 才会输出 `[B,3]`，因此形状取决于调用时输入。

#### `make_keyframe_inputs`

原文件：`src/data.py`，第 73 行起。

```python
def make_keyframe_inputs(pose):
    batch, frames, joints, xy = pose.shape
    mask = torch.zeros(batch, frames, 1, device=pose.device)
    indices = (0, frames // 2, frames - 1)
    mask[:, list(indices), :] = 1.0
    sparse_pose = pose * mask.unsqueeze(-1)
    return sparse_pose.reshape(batch, -1), mask.reshape(batch, -1), mask
```

解包 `[B,T,J,2]`；创建 `[B,T,1]` 的全零 mask，并在索引 0、12、23 置 1。这里中间帧指零起始编号 12，即第 13 帧。

`mask.unsqueeze(-1)` 变成 `[B,T,1,1]`，通过广播与每帧所有关节坐标相乘。只保留三帧，其余置零。保留 mask 是为了区分“没有给出这一帧”和“这一帧坐标真的为零”。返回稀疏坐标 `[B,240]`、展平 mask `[B,24]`、原始 mask `[B,24,1]`。`reshape(batch,-1)` 的 -1 表示自动计算剩余维度。

##### mask 是“这一页有没有给答案”的开关表

用 B=1、T=5、J=1 的缩小例子手算。每页只有一个点：

```text
pose = [(0.1,0.2),(0.2,0.3),(0.3,0.4),(0.4,0.5),(0.5,0.6)]
indices = (0,2,4)
mask    = [1,0,1,0,1]
sparse  = [(0.1,0.2),(0,0),(0.3,0.4),(0,0),(0.5,0.6)]
```

这个缩小例子只展示辅助函数的行为，不代表当前模型接受 5 帧输入。

`batch,frames,joints,xy = pose.shape` 像把 `(1,5,1,2)` 四个数字分别放进四个名字。mask 的末尾只有一个数，是“整页共享的开关”。unsqueeze 增加长度为 1 的轴，让这个开关能广播到每个关节的 x、y，意思是同一帧的坐标全部乘同一个开关。

`mask[:,list(indices),:] = 1.0` 中的冒号表示选取该轴全部元素：所有样本、指定三帧、最后轴全部位置。

展平像把多页坐标表按固定次序抄到一长行。`reshape` 保留这些数及其顺序，不会插值、不删除为零的帧，也不会学习补全。返回三个结果是元组打包，调用者用三个名字按顺序接收。

#### `build_condition`

原文件：`train.py`，第 44 行起。

```python
def build_condition(batch, experiment):
    gloss = make_gloss_one_hot(batch["gloss"])
    if experiment == "multi_condition":
        # 五档量化是 FSQ 思路的课堂演示，不是完整 FSQ 自编码器。
        continuous = batch["extra"].clamp(-1.0, 1.0)
        quantized = torch.round((continuous + 1.0) * 2.0) / 2.0 - 1.0
        return torch.cat([gloss, quantized], dim=1)
    return gloss
```

先生成 `[B,3]` 类别条件。只有 multi_condition 会读取额外条件：`clamp` 限制范围，公式把 [-1,1] 映射到 [0,4] 后取最近整数（恰好一半时取偶数），再映射回来，得到 `{-1,-0.5,0,0.5,1}` 五档。

例如 0.30 会变成 0.5；方向 ±1 则保留。拼接后是 `[B,6]`。`dim=1` 表示沿特征维拼接，样本数不变。这是输入数值量化示例，没有学习编码器、码本或完整 FSQ 自编码器。量化也会丢掉部分精度。

##### 从样本包中取出“允许模型看到的线索”

同一个字典包含题目线索和答案，网络不会自动看到全部内容；这个函数像出题老师决定把哪些提示印在试卷上。

假设某样本 gloss=2、extra=`[1,0.3,-0.6]`（手选示例）：

```text
baseline：condition = [0,0,1]
multi_condition：condition = [0,0,1, 1,0.5,-0.5]
                             类别    量化条件
```

具体看 0.3：`(0.3+1)×2=2.6 → round=3 → 3/2-1=0.5`。看 -0.6：`(-0.6+1)×2=0.8 → round=1 → 1/2-1=-0.5`。

`continuous` 指向范围限制后的张量，`quantized` 指向量化结果；它们不是分别训练的层。`clamp` 像限位器，将例如 1.2 截到 1。`cat` 像把两张同样行数的表横向接起来，B 行仍是 B 行，只多了三列。

`gloss` 在这个函数里已是 one-hot 张量，虽然变量名与 Dataset 中整数 gloss 一样，含义已经变了。阅读代码要结合所在函数，而不是认为同名变量总保存相同类型。

补充精确规则：`torch.round` 在恰好一半时取最近的偶数，不是所有边界都按日常“逢五进一”；例如映射值 2.5 会取 2。已有 0.3 的例子不在这个边界上。

#### `build_model`

原文件：`train.py`，第 54 行起。

```python
def build_model(experiment):
    if experiment in ("baseline", "bone"):
        return PoseMLP(NUM_GLOSSES)
    if experiment == "temporal":
        return TemporalPoseNet(NUM_GLOSSES)
    if experiment == "diffusion":
        return NoisePredictor(NUM_GLOSSES)
    if experiment == "multi_condition":
        return PoseMLP(NUM_GLOSSES + 3)
    if experiment == "multi_head":
        return MultiHeadPoseNet(NUM_GLOSSES)
    if experiment == "keyframe":

        return KeyframePoseNet(NUM_GLOSSES, key_dim)

```

把实验名映射到网络。baseline 和 bone 使用相同 PoseMLP，区别仅在损失；temporal 换成时序网络；diffusion 使用噪声预测器；multi_condition 的 MLP 多接收 3 个条件；multi_head 共享特征后分两个输出头。

keyframe 中 `key_dim=24×10+24=264`，加上 3 个类别特征，网络实际输入维度为 267。这里先构造模型，`main()` 再把它移到设备。最后的 `ValueError` 防止未知实验名悄悄走错分支。

##### 网络工厂：先组装机器，再给它喂题

`build_model("baseline")` 返回一个 PoseMLP 对象；`build_model("diffusion")` 返回 NoisePredictor 对象。这类似按订单选择不同机器型号。返回的不是预测动作，也不是训练后的权重文件。

```text
model = build_model("baseline")  → 得到带初始权重的网络对象
prediction = model(condition)    → 才对一批输入计算预测
```

`NUM_GLOSSES` 为 3，所以 PoseMLP 入口要接收三列。multi_condition 多三个条件，所以入口必须改为 6；否则向要求 3 列的层送入 6 列会造成矩阵形状不匹配。

`return` 会立即结束函数，因此命中 baseline 后不会继续创建其他模型。最后的 raise 像工厂拒绝不认识的型号，避免返回一个不明确的结果。

#### `prepare_input`

原文件：`train.py`，第 71 行起。

```python
def prepare_input(batch, experiment):
    condition = build_condition(batch, experiment)
    if experiment == "keyframe":
        sparse_pose, mask_flat, mask = make_keyframe_inputs(batch["pose"])
        return torch.cat([condition, sparse_pose, mask_flat], dim=1), mask
    return condition, None
```

普通实验返回 `(condition,None)`。关键帧实验先从标准答案中抽取三帧作为已知条件，然后拼接 `[类别3, 稀疏坐标240, mask24]`，得到 `[B,267]`；另返回未展平 mask 给损失函数。

这是“已知部分动作补全其余动作”的任务，因此输入包含目标的三帧是设计的一部分。不能据此声称模型仅凭类别完成了同样的预测。

##### 把线索装订成模型真正接收的一行

普通实验把 `[B,3]` 或 `[B,6]` 条件直接交给模型，并返回 None 表示“不需要关键帧 mask”。None 是 Python 的空值标记，不是数值 0，也不是一个全零张量。

关键帧实验中，一个样本的长行按以下顺序排列：

```text
[类别的3个数 | 24帧×10坐标的240个数 | 24个帧开关]
                          共267个数
```

`sparse_pose,mask_flat,mask = ...` 是接收三个返回值，不是在同一个数组里查找这三个名字。最后 `return 输入,mask` 再把两个值交给调用者。

后续 `model_input,mask = prepare_input(...)` 左边按顺序接收：第一个用于前向计算，第二个只辅助计算关键帧损失。已经给出的三帧属于题目条件，其余 21 帧仍是要学习预测的答案。

#### `pose_objective`

原文件：`train.py`，第 79 行起。

```python
def pose_objective(prediction, target, experiment, args, mask):
    loss = coordinate_loss(prediction, target)
    if experiment == "bone":
        loss = loss + args.bone_weight * bone_vector_loss(prediction, target)
    if experiment == "temporal":
        loss = loss + args.smooth_weight * velocity_loss(prediction, target)
    if experiment == "keyframe":
        loss = loss + keyframe_loss(prediction, target, mask)
    return loss
```

所有非扩散实验都包含坐标 MSE。bone 加 `0.25 × 骨骼向量 MSE`；temporal 加 `0.10 × 速度 MSE`；keyframe 加关键帧 MSE。其余实验只用坐标 MSE。

额外项相加形成一个标量，再一起反向传播。权重影响不同约束的重要程度；不同实验的总损失定义不同，不能直接以总损失数值大小判定哪个实验更好。

##### 把几项扣分合成一个总分

假设某批次坐标误差 0.04、骨骼误差 0.02：

```text
baseline 总损失 = 0.04
bone 总损失     = 0.04 + 0.25×0.02 = 0.045
```

bone 的总数更大，并不能说明坐标预测更差，因为加了新的扣分项目。权重 0.25 像给骨骼项目设置计分比例，不是四分之一的样本参与，也不是训练后再手工修骨长。

`loss = loss + ...` 让 loss 这个名字指向新的总损失张量。训练时这不是普通 Python 小数：它还连着产生预测的计算过程，backward 能沿这些连接把多个项目的影响传回参数。只有日志处 `.item()` 才取出普通数字。

#### `run_epoch`

原文件：`train.py`，第 90 行起。

```python
def run_epoch(model, loader, optimizer, experiment, args, device, schedule):
    training = optimizer is not None
    model.train(training)
    total_loss = 0.0
    total_samples = 0

    for batch in loader:
        batch = {name: value.to(device) for name, value in batch.items()}
        target = batch["pose"]
        if experiment == "diffusion":
            clean = target.reshape(target.shape[0], -1)
            noise = torch.randn_like(clean)
            time_index = torch.randint(
                0, args.diffusion_steps, (target.shape[0],), device=device
            )
            noisy = add_noise(clean, noise, time_index, schedule[2])
            condition = make_gloss_one_hot(batch["gloss"])
            time = time_index.float() / max(args.diffusion_steps - 1, 1)
            prediction = model(noisy, condition, time)
            loss = F.mse_loss(prediction, noise)
        else:
            model_input, mask = prepare_input(batch, experiment)
            prediction = model(model_input)
            loss = pose_objective(prediction, target, experiment, args, mask)

        if training:
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()

        count = target.shape[0]
        total_loss += loss.detach().item() * count
        total_samples += count

    return total_loss / max(total_samples, 1)
```

1. `optimizer is not None` 决定是否训练；`model.train(training)` 在训练模式与评估模式间切换。当前网络没有 Dropout/BatchNorm，两种模式的前向行为基本相同，但保留了规范接口。
2. 遍历 loader，每次拿一个批次；字典推导式把所有张量搬到同一个 CPU/GPU。`target` 为 `[B,24,5,2]`。
3. 普通分支准备条件、前向预测、计算姿态损失，输出形状与 target 一致。
4. 扩散分支把动作展平为 `[B,240]`；生成同形状的标准高斯噪声；给每个样本独立抽取时间步；按计划加噪；把时间归一化到 [0,1]；模型预测噪声，并与真实噪声计算 MSE。这里 `prediction` 的含义是噪声，不是动作。
5. 训练时先 `zero_grad()` 清除上一次梯度，再 `loss.backward()` 用链式法则计算参数梯度，最后 `optimizer.step()` 让 Adam 更新权重。若没有清零，PyTorch 默认会累积梯度。
6. `loss.detach().item()` 从计算图取出普通数值，只用来记录。损失乘批次实际样本数后累加，最后除总样本数；这样最后一个小批次不会被赋予与完整批次相同的权重。

验证调用者还要使用 `torch.no_grad()`：评估模式本身不会关闭梯度。扩散验证每次会重新抽噪声和时间步，因此验证损失可能因随机抽样而波动。

##### 先看每个名字实际装什么

| 名字 | 内容 | 比喻 |
| --- | --- | --- |
| model | 神经网络对象 | 正在练习的解题机器 |
| loader | DataLoader 对象 | 按批递交试卷的工作人员 |
| optimizer | Adam 对象，验证时为 None | 根据梯度调整机器的工具 |
| training | True/False | 本轮是否允许更新参数 |
| batch | 按字段组织的张量字典 | 本次收到的一叠题目与答案 |
| target | batch 中的真实动作张量 | 标准答案 |
| prediction | 模型输出张量 | 机器答卷，扩散分支中则是噪声答卷 |
| loss | 标量张量 | 可反传的扣分结果 |
| total_loss、total_samples | Python 数值累计器 | 统计整轮平均分的账本 |

`optimizer is not None` 是身份判断，意思是“是否确实传入了优化器”。这里 model.train(True) 的 train 容易让人误会：它只是设置模式开关，不会自己迭代数据或调整权重，真正更新发生在下面三行。

##### 普通回归分支：两份答卷怎么批改？

假设 B=2，类别 `[2,0]`，目标为两段动作：

```text
batch["gloss"] [2]
     ↓ prepare_input（baseline）
model_input    [2,3]
     ↓ model
prediction     [2,24,5,2]
     ↓ 与 target 同形状逐项比较
loss           []，例如 tensor(0.04, grad_fn=...)
```

`.to(device)` 像把题目和机器放到同一个工作台。GPU 张量和 CPU 参数通常不能直接共同计算，所以 batch 和 model 都要移到同一设备。字典推导式 `{name:value.to(device) for ...}` 是逐个字段构建新字典；name 是字符串键，value 是对应张量，并非只移动字段名字。

##### 三行更新：先清账、再求方向、最后调整

```python
optimizer.zero_grad()  # 清除参数上一次留下的梯度
loss.backward()       # 计算本次损失对参数的梯度
optimizer.step()      # Adam 使用梯度更新参数
```

用单参数的假想问题帮助理解：预测 `y=w×1`，目标为 2，当前 w=1。损失 `(w-2)²=1`，梯度为 `2(w-2)=-2`。若用学习率 0.1 的普通梯度下降，w 更新为 `1-0.1×(-2)=1.2`，下次损失变为 0.64。

这个手算只解释梯度方向，**当前代码用 Adam，并不会照这个 SGD 公式必然更新到 1.2**。Adam 还保存梯度的历史统计。backward 负责得到梯度，本身不执行 Adam 更新；step 不会自动重新计算这批预测，改进要在后续前向中观察。

##### 整轮均值：为什么先乘样本数？

假设共 5 个样本，批大小 3。第一批 3 个样本平均损失 0.1，第二批 2 个平均损失 0.4：

```text
total_loss    = 0.1×3 + 0.4×2 = 1.1
total_samples = 3 + 2 = 5
整轮平均       = 1.1/5 = 0.22
```

直接平均两批得到 0.25，会让小批次占过大的比例。`.detach()` 将用于统计的结果与求导图分开；`.item()` 取出单个 Python 数值，这个数不会再参与反向传播。

##### 扩散分支：老师已知道污点，训练机器把污点指出来

`clean` 是展平的真实动作；`noise` 是人为生成、因此已知的噪声；`noisy` 是混合后的输入。不要把这三个名字当成同一份数据。

例如 B=2、50 步，某次抽到 `time_index=[0,49]`：

```text
clean      [2,240]：两段干净动作
noise      [2,240]：两份独立噪声
time_index [2]：每个样本各自的加噪强度编号
time       [2]：[0.0,1.0]，只是编号归一化
noisy      [2,240]：按各自强度混合
prediction [2,240]：模型猜噪声
loss：prediction 对 noise 的 MSE
```

`randn_like` 里的 like 表示按 clean 的形状、设备和浮点类型创建噪声，不是“噪声的数值接近 clean”。`torch.randint` 的上界不包含，故 50 步对应编号 0～49。

训练时每个样本直接构造一个随机强度的题目，不需要先执行 50 次完整去噪。验证的目标也是噪声，但不更新参数；每次重新抽题中的噪声与时间，所以验证曲线会有随机波动。

#### `make_preview`

原文件：`train.py`，第 127 行起。

```python
@torch.no_grad()
def make_preview(model, dataset, experiment, args, device):
    sample = dataset[0]
    batch = {
        name: value.unsqueeze(0).to(device)
        for name, value in sample.items()
    }
    target = batch["pose"]

    if experiment == "diffusion":
        condition = make_gloss_one_hot(batch["gloss"])
        flat = sample_pose(
            model, condition, args.diffusion_steps,
            NUM_FRAMES * POSE_DIM, device,
        )
        prediction = flat.reshape(1, NUM_FRAMES, POSE_DIM // 2, 2)
    else:
        model_input, _ = prepare_input(batch, experiment)
        prediction = model(model_input)

    return target[0].cpu().numpy(), prediction[0].cpu().numpy(), int(sample["gloss"])
```

`@torch.no_grad()` 关闭本函数中的梯度记录。取验证集第 0 个样本，给每个字段增加批次维，形成 B=1 的输入。

扩散实验从随机噪声采样，再还原 `[1,24,5,2]`；其余实验直接前向。`[0]` 去掉批次维，`.cpu().numpy()` 把结果交给绘图库。返回目标、预测、类别编号。

这里只画一个样本，不能代表整个验证集。非扩散分支依靠上一轮验证留下的 eval 模式；若脱离 main 单独调用，宜显式设置 `model.eval()`。

##### 一个人也要装进“批次盒子”

Dataset 的单样本 pose 是 `[24,5,2]`，网络却按 `[B,...]` 接收数据。`unsqueeze(0)` 像给一份材料再套上外层盒子：

```text
gloss []       → [1]
extra [3]      → [1,3]
pose [24,5,2]  → [1,24,5,2]
```

这不是生成新样本，也不是把所有数加 1；只是增加一个长度为 1 的维度。`target[0]` 和 `prediction[0]` 在输出时再拆掉盒子，交给不接收批次维的绘图函数。

`flat` 这个名字提示“展平结果”，扩散生成后需按固定规则重新排成帧、关节、坐标。非扩散的 `model_input,_ = ...` 用下划线表达“接到第二个返回值但不准备使用它”，并不是该函数只返回一个值。

`.cpu().numpy()` 像从计算工作台取回数据并换成绘图工具认识的容器。装饰器已关闭求导，因此这里无需再对输出 detach。预览本身不会让模型变得更好，只是观察已训练参数的表现。

#### `main`

原文件：`train.py`，第 150 行起。

```python
def main():
    args = parse_args()
    torch.manual_seed(args.seed)
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

    train_data = ToySignDataset(args.samples, seed=args.seed)
    val_data = ToySignDataset(max(args.samples // 4, 128), seed=args.seed + 100_000)
    train_loader = DataLoader(train_data, batch_size=args.batch_size, shuffle=True)
    val_loader = DataLoader(val_data, batch_size=args.batch_size, shuffle=False)

    model = build_model(args.experiment).to(device)
    optimizer = torch.optim.Adam(model.parameters(), lr=args.learning_rate)
    schedule = make_noise_schedule(args.diffusion_steps, device)

    train_losses, val_losses = [], []
    print(f"实验：{args.experiment} | 设备：{device}")
    print(f"动作类别：{', '.join(GLOSS_NAMES)}")

    for epoch in range(1, args.epochs + 1):
        train_loss = run_epoch(
            model, train_loader, optimizer, args.experiment, args, device, schedule
        )
        with torch.no_grad():
            val_loss = run_epoch(
                model, val_loader, None, args.experiment, args, device, schedule
            )
        train_losses.append(train_loss)
        val_losses.append(val_loss)
        print(
            f"Epoch {epoch:03d}/{args.epochs} | "
            f"train_loss={train_loss:.6f} | val_loss={val_loss:.6f}"
        )

    output_dir = Path(args.output_dir)
    output_dir.mkdir(parents=True, exist_ok=True)
    csv_path = output_dir / f"{args.experiment}_loss.csv"
    with csv_path.open("w", newline="", encoding="utf-8") as file:
        writer = csv.writer(file)
        writer.writerow(["epoch", "train_loss", "val_loss"])
        for epoch, values in enumerate(zip(train_losses, val_losses), start=1):
            writer.writerow([epoch, *values])

    target, prediction, gloss_id = make_preview(
        model, val_data, args.experiment, args, device
    )
    image_path = output_dir / f"{args.experiment}_preview.png"
    save_pose_comparison(
        target, prediction, image_path,
        f"{args.experiment}: {GLOSS_NAMES[gloss_id]}",
    )
    curve_path = output_dir / f"{args.experiment}_curve.png"
    save_loss_curve(train_losses, val_losses, curve_path, args.experiment)

    print(f"损失记录：{csv_path}")
    print(f"动作对比图：{image_path}")
    print(f"训练曲线：{curve_path}")
```

按执行顺序阅读：

1. 解析参数，设置 PyTorch 随机种子，优先选择可用的 CUDA，否则用 CPU。数据集随机性由各自 NumPy 发生器控制。固定种子有助复现，但不保证所有设备上完全相同。
2. 创建训练集和验证集。验证数量为 `max(samples//4,128)`；种子起点相差 100000。默认规模下两者样本种子不重叠；这不是对任意超大样本量都严格成立的隔离方案。
3. DataLoader 负责分批和堆叠字典。训练打乱顺序，验证保持顺序；没有改变样本内部 24 帧的顺序。
4. 创建网络、搬到设备，用 `model.parameters()` 把可训练参数交给 Adam。所有实验都会创建噪声计划，但非扩散实验不使用它。
5. 每轮训练一次，随后在 `no_grad()` 中验证一次。把两个均值放进列表，用格式化字符串输出轮数和六位小数损失。epoch 是遍历完整训练集；batch 是其中的一小组；默认 1024/64=16 次更新构成一轮。
6. 创建输出目录，用 UTF-8 CSV 写表头，再通过 `enumerate(zip(...),start=1)` 写轮数和对应损失。`with` 保证文件关闭；`newline=""` 避免 CSV 的多余空行问题。
7. 生成一个验证样本的对比图和训练/验证曲线，打印路径。当前代码没有保存模型权重，也没有动画或真实视频输出。同一输出目录重复跑同名实验会覆盖该实验的三个文件。

入口 `if __name__ == "__main__": main()` 表示直接运行此文件才启动训练；其他模块导入它时只得到函数定义。

##### main 是总调度员，不是一个额外的网络层

用命令 `python train.py --experiment baseline --epochs 2 --samples 8 --batch_size 3` 跟踪一次流程（手动指定的小规模示例）：

```text
args：2轮、8个训练样本、每批3个
train_data：8个可按编号生成的样本
val_data：max(8//4,128)=128个验证样本
train_loader：每轮分成3、3、2三个批次
model：新建随机初始化的PoseMLP
optimizer：绑定这些参数的Adam
第1轮：3次训练更新 → 验证，不更新
第2轮：3次训练更新 → 验证，不更新
保存2行损失记录 → 画验证集第0个样本 → 画2个点的曲线
```

`8//4` 是整除结果 2；`max(2,128)` 取较大值，所以小训练集也会有至少 128 个验证样本。不要以为 --samples=8 就只会生成总计 8 个样本。

`device = torch.device("cuda" if ... else "cpu")` 使用条件表达式，相当于根据可用性选择工作台；构建一个 device 对象不等于已经搬动网络。后面的 `.to(device)` 才搬动参数或张量。

`model.parameters()` 提供网络可训练参数。优化器拿到的是这些参数的引用，所以 step 调整的正是 model 后面继续使用的数值，不是另建一个“改进版模型”变量。

`train_losses,val_losses = [],[]` 创建两个独立列表，像分别记训练与考试成绩的本子。`.append` 每轮添一项。假设记录分别是 `[0.20,0.10]` 和 `[0.23,0.15]`，CSV 写出的两行数据就是 `1,0.20,0.23` 和 `2,0.10,0.15`。

保存路径中 `/` 是 Path 的拼接操作，不是做除法：`Path("outputs") / "baseline_loss.csv"` 得到文件路径。`mkdir(parents=True,exist_ok=True)` 创建所需目录，已存在也允许继续。

`writer` 是 CSV 写入对象，`writerow` 负责写一行，不是神经网络层。`zip` 将两本成绩本按轮配对；`enumerate(...,start=1)` 给每对成绩编号；`[epoch,*values]` 将二元 values 拆开，组成三项列表。

`f"Epoch {epoch:03d}"` 中的 f 表示把变量填进文本，03d 表示整数至少三位，不足补零，如 2 显示成 002；`.6f` 则把浮点数格式化为六位小数，只影响日志显示，不改变训练精度。

最后打印路径仅告诉你文件在哪里；没有保存 `.pt` 权重。重新运行会重新初始化模型，不会自动接着上次训练。

## 第三章：基础模型、时序模型和损失

| 实验 | 输入 | 网络 | 目标 |
| --- | --- | --- | --- |
| baseline | 类别 | MLP | 坐标 MSE |
| bone | 类别 | 同一个 MLP 结构 | 坐标 + 骨骼向量误差 |
| temporal | 类别与内部时间 | 逐帧 MLP + 时间卷积 | 坐标 + 速度误差 |

baseline 与 bone 可以观察只改损失的影响。但 temporal 同时换了网络和损失，当前代码不能把其差异单独归因于时间卷积。若要严格对照，可在掌握后设计“同网络有/无速度损失”等实验。

同一类别的目标存在左右方向、尺度、位置和速度变化，而 baseline 只收到类别。确定性模型对同一输入只能输出同一结果；平方误差会推动它接近条件均值。左右镜像平均后，预测可能靠近根节点，出现幅度缩小。这未必是反向传播写错，而是条件信息不足与损失选择共同导致的。


## 第三章 A：逐个网络解析（进阶网络可稍后返回阅读）

`nn.Module` 是网络基类；`super().__init__()` 初始化模块管理机制，使层的参数能被 `parameters()` 找到。`__init__` 定义可训练层，`forward` 描述输入怎样变为输出。调用 `model(x)` 时 PyTorch 会进入 forward，并处理相关模块机制。

`nn.Linear(in,out)` 对最后一维做仿射变换 `y=xWᵀ+b`；`ReLU` 逐元素取 `max(0,x)`，提供非线性；`Sequential` 依次运行其中的层。

### 导入与文件级定义

```python
"""基础 MLP 以及逐步加入时序、条件和多头结构的模型。"""
import torch
from torch import nn
from src.data import NUM_FRAMES, POSE_DIM
```

### `PoseMLP`

基础网络一次输出全部帧坐标，不需要逐帧循环。baseline 和 bone 都使用它。

#### `PoseMLP.__init__`

原文件：`src/models.py`，第 8 行起。

```python
def __init__(self, condition_dim, hidden_dim=256):
    super().__init__()
    self.network = nn.Sequential(
        nn.Linear(condition_dim, hidden_dim),
        nn.ReLU(),
        nn.Linear(hidden_dim, NUM_FRAMES * POSE_DIM),
    )
```

默认构成 `3 → 256 → 240`。隐藏维 256 是可调的容量设置，240 来自 24 帧 × 5 点 × 2 坐标。末层没有激活函数，所以坐标可超出 [0,1]。baseline 参数数为 `(3×256+256)+(256×240+240)=62704`。

##### 把模型想成装配好的三站流水线

`self.network` 是注册在模型对象里的一个 Sequential 模块，不是 256 个预测结果。它保存层及其权重，后面收到输入才开始运算。

```text
类别三盏灯 → Linear(3,256) → ReLU → Linear(256,240)
             混合成256项特征          输出240个坐标数
```

理解 Linear 可以先缩成一条公式，假设某个隐藏单元的权重为 `[0.2,-0.4,0.6]`，偏置为 -0.1：

```text
输入 [0,0,1]
输出 = 0×0.2 + 0×(-0.4) + 1×0.6 - 0.1 = 0.5
```

这是手选权重的教学例子，实际初始权重由 PyTorch 初始化。256 个隐藏单元各自有一组权重和偏置，不是同一个 0.5 复制 256 次。

ReLU 像只允许非负值通过的阀门：`[-0.3,0.5,0] → [0,0.5,0]`。第二个 Linear 再根据这些中间特征输出坐标。隐藏特征没有预先规定“第一个必然是肘角”等物理意义。

`super().__init__()` 先完成 nn.Module 的基础设置，让这些层能被 PyTorch 追踪。把层保存在 `self.network` 中后，外部 optimizer 才能通过 model.parameters 找到它们。

#### `PoseMLP.forward`

原文件：`src/models.py`，第 16 行起。

```python
def forward(self, condition):
    output = self.network(condition)
    return output.reshape(-1, NUM_FRAMES, POSE_DIM // 2, 2)
```

`[B,3] → [B,240] → [B,24,5,2]`。reshape 只重新解释维度，不额外学习，也不把动作按时间递归生成。-1 在这里自动推断批次大小。

##### 240 个数怎样重新变成动作？

假设 B=1，输出向量开头是 `[0.50,0.78,0.66,0.90,...]`。reshape 后：

```text
prediction[0,0,0] = [0.50,0.78]  第0个样本、第0帧、第0点
prediction[0,0,1] = [0.66,0.90]  第0个样本、第0帧、第1点
...
向量下标0～9    → 第0帧的5个点
向量下标10～19  → 第1帧的5个点
```

像把一长行名单折成每页 5 行、每行 2 列，数值与顺序没有改变。`POSE_DIM//2=5`，因为每点有两个坐标。若 B=2，总数为 480，`reshape(-1,24,5,2)` 自动推断首维 `480/(24×5×2)=2`。

`output` 是 network 本次计算得到的张量；它与定义层时的 `self.network` 是两种东西：前者是产品，后者是生产线。`model(condition)` 会进入 forward；定义模型时不会把整个训练集计算一遍。

### `TemporalPoseNet`

先根据类别和当前时间生成每帧粗预测，再利用一维卷积混合相邻时间的信息。

#### `TemporalPoseNet.__init__`

原文件：`src/models.py`，第 22 行起。

```python
def __init__(self, condition_dim, hidden_dim=64):
    super().__init__()
    self.frame_mlp = nn.Sequential(
        nn.Linear(condition_dim + 1, hidden_dim),
        nn.ReLU(),
        nn.Linear(hidden_dim, POSE_DIM),
    )
    self.temporal = nn.Sequential(
        nn.Conv1d(POSE_DIM, hidden_dim, 3, padding=1),
        nn.ReLU(),
        nn.Conv1d(hidden_dim, POSE_DIM, 3, padding=1),
    )
```

`frame_mlp` 接收类别条件加 1 个时间值，做 `4→64→10`。`temporal` 做通道 `10→64→10` 的两层时间卷积；核宽 3，默认步幅 1，padding=1 让输出帧数仍为 24。这里的通道是坐标特征，卷积移动的方向是时间。

##### 两道工序：先画每页，再让相邻页商量

frame_mlp 为每帧读取“类别三项 + 时间一项”，像画师根据动作类型和翻页位置先画出一页草图。temporal 再观察附近几页，学着修改草图，让前后协调。

用单通道、卷积权重 `[1/3,1/3,1/3]` 的假想例子：时间数列 `[0,3,6,9]` 中，围绕 6 的窗口 `[3,6,9]` 计算平均为 6。它说明“移动窗口”的含义；实际 Conv1d 会同时混合多个通道，权重可训练，并不是固定均值滤波。

核宽 3 表示一次看三个相邻时间位置。padding=1 像在两端各补一个空位置，避免长度每卷积一层缩短。64 是中间通道数，既不是 64 帧，也不是 64 个关节。

#### `TemporalPoseNet.forward`

原文件：`src/models.py`，第 35 行起。

```python
def forward(self, condition):
    batch = condition.shape[0]
    time = torch.linspace(0, 1, NUM_FRAMES, device=condition.device)
    time = time.view(1, NUM_FRAMES, 1).expand(batch, -1, -1)
    repeated = condition.unsqueeze(1).expand(-1, NUM_FRAMES, -1)
    coarse = self.frame_mlp(torch.cat([repeated, time], dim=-1))
    residual = self.temporal(coarse.transpose(1, 2)).transpose(1, 2)
    pose = coarse + residual
    return pose.reshape(-1, NUM_FRAMES, POSE_DIM // 2, 2)
```

1. 在输入所在设备创建 `[24]` 时间序列，经 view 和 expand 得到 `[B,24,1]`。
2. 类别条件从 `[B,3]` 扩展为 `[B,24,3]`，每帧都收到同一类别；expand 是扩展视图，通常不实际复制全部数据。
3. 拼接为 `[B,24,4]`，MLP 对最后一维运算，得到 coarse `[B,24,10]`。
4. Conv1d 要求 `[B,通道,时间]`，因此转置为 `[B,10,24]`；卷积后再转回来。
5. `coarse+residual` 表示在粗预测上学习修正量。两层宽 3 卷积在粗特征上的局部感受野最多为 5 帧，边界使用零填充。最终整理为标准姿态形状。

它一次处理整段序列，能看见相邻前后帧，不是只能看过去的自回归模型。

##### 跟着一个样本看每张表的内容

若输入为指向类别 `[0,0,1]`，前两帧进入 frame_mlp 的内容是：

```text
第0帧：[0,0,1, 0.000000]
第1帧：[0,0,1, 0.043478]  # 1/23
...
第23帧：[0,0,1, 1.000000]
```

time 区分不同帧。没有时间，重复的类别经过同一个逐帧 MLP 会得到相同粗预测，难以表达动作进度。

`unsqueeze(1)` 在样本与特征之间加帧轴；`expand` 像告诉读取者“每一帧都参考这同一组类别灯”。它不新建 24 个不同类别。time 的 expand 中 -1 表示该维保持原大小，而 reshape 的 -1 表示推断维度；相同写法要结合所用函数理解。

`transpose(1,2)` 像把“每行一帧、每列一个坐标”的表转成“每行一个坐标随时间的变化”。数据没有被重新预测，只是调整轴的顺序以符合 Conv1d 接口。

`coarse` 是粗草图，`residual` 是修改量。例如某坐标 coarse=0.40、residual=-0.03，则 pose=0.37。模型在学修正，不是把两段动作接在一起；因此这里用加法，而不是 cat。

### `MultiHeadPoseNet`

“多头”指共享隐藏特征后分支输出，不是 Transformer 的多头注意力。此处 body/hand 只是对 5 个链上点的教学划分。

#### `MultiHeadPoseNet.__init__`

原文件：`src/models.py`，第 47 行起。

```python
def __init__(self, condition_dim, hidden_dim=128):
    super().__init__()
    self.shared = nn.Sequential(nn.Linear(condition_dim, hidden_dim), nn.ReLU())
    self.body_head = nn.Linear(hidden_dim, NUM_FRAMES * 3 * 2)
    self.hand_head = nn.Linear(hidden_dim, NUM_FRAMES * 2 * 2)
```

共享层把类别 3 维变成 128 维；body_head 输出 `24×3×2=144` 个坐标，hand_head 输出 `24×2×2=96` 个坐标。两个头参数独立，但都依赖同一共享特征。

##### 一个共用准备台，两个绘图出口

`shared` 类似先分析动作类别的公共准备台。body_head 和 hand_head 是两个单独学习的出口：前者负责 3 个点，后者负责 2 个点。

```text
类别3项 → 共享128项特征 ┬→ body_head：144个数
                       └→ hand_head：96个数
```

两个 Linear 都收到同一份共享特征，但各有自己的权重。不是先得到身体再把它输入手部头；也没有两个独立优化器，现有 Adam 会统一更新全部参数。

#### `MultiHeadPoseNet.forward`

原文件：`src/models.py`，第 53 行起。

```python
def forward(self, condition):
    hidden = self.shared(condition)
    body = self.body_head(hidden).reshape(-1, NUM_FRAMES, 3, 2)
    hand = self.hand_head(hidden).reshape(-1, NUM_FRAMES, 2, 2)
    return torch.cat([body, hand], dim=2)
```

共享特征 `[B,128]` 分别变成 `[B,24,3,2]` 与 `[B,24,2,2]`，沿关节维 dim=2 拼接成 `[B,24,5,2]`。普通坐标损失会同时训练两个头和共享层。没有额外保证两个分支连接位置合理的硬约束。

##### cat 是拼接，不是相加

把某一帧的 body 想成 `[点0,点1,点2]`，hand 想成 `[点3,点4]`，沿关节维拼接就是 `[点0,点1,点2,点3,点4]`。

`dim=2` 选的是 `[B,时间,关节,坐标]` 中从 0 开始数的第三根轴。若沿时间轴拼接，含义会变成增加帧数，且当前其余维也不匹配；因此不能仅凭“都叫拼接”随意改 dim。

`hidden` 是本次输入计算出的中间张量，不是网络层对象。body 与 hand 都由它计算，所以两个输出的误差都会对 shared 的参数产生梯度。

### `KeyframePoseNet`

根据类别、已知三帧和 mask 一次补全整段动作。它是条件 MLP，不是专门的插值公式。

#### `KeyframePoseNet.__init__`

原文件：`src/models.py`，第 61 行起。

```python
def __init__(self, condition_dim, keyframe_input_dim, hidden_dim=256):
    super().__init__()
    self.network = nn.Sequential(
        nn.Linear(condition_dim + keyframe_input_dim, hidden_dim),
        nn.ReLU(),
        nn.Linear(hidden_dim, hidden_dim),
        nn.ReLU(),
        nn.Linear(hidden_dim, NUM_FRAMES * POSE_DIM),
    )
```

输入 267 维，经过 `267→256→256→240`。与基础模型相比多了一层隐藏层，还接收了部分真实坐标；因此不能将其表现差异完全归因于“多一层”。

##### 这次试卷上附带了三页参考答案

`condition_dim` 记录类别列数 3，`keyframe_input_dim` 记录稀疏坐标与开关列数 264，第一层因此需要 267 列。参数名中的 dim 是维度数字，不是实际数据本身。

网络层定义只规定“能接多少列、输出多少列”。真正的类别、三帧数值及 mask 是后续 prepare_input 拼好的 inputs，不在构造函数里写死。

多一层隐藏层可以增强表示能力，但不会自动让网络遵守关键帧。关键帧是否贴合，还取决于输入、训练和损失。

#### `KeyframePoseNet.forward`

原文件：`src/models.py`，第 71 行起。

```python
def forward(self, inputs):
    output = self.network(inputs)
    return output.reshape(-1, NUM_FRAMES, POSE_DIM // 2, 2)
```

输入已由 prepare_input 拼好；输出 240 个数，再变为 `[B,24,5,2]`。它会重新预测所有帧，包括已知帧。代码没有直接把已知帧拷回输出，因此仅通过损失鼓励接近，不能保证逐点完全一致。

##### 补全不是原样复印

例如已知根节点 x=0.50，网络仍可能输出 0.49，因为末层会重新计算所有 240 个坐标。即使输入中已经给了 0.50，也没有一条“照抄”的硬性赋值。

`output` 是 240 列的整段预测；reshape 只是整理成动作。后面的 keyframe_loss 会对 0.49 与 0.50 的偏差扣分，逐步鼓励保留已知信息，但不保证完全相等。

### `NoisePredictor`

扩散模型预测加到动作上的噪声 ε。网络输出形状与展平动作相同，但语义不同。

#### `NoisePredictor.__init__`

原文件：`src/models.py`，第 77 行起。

```python
def __init__(self, condition_dim, hidden_dim=256):
    super().__init__()
    self.network = nn.Sequential(
        nn.Linear(NUM_FRAMES * POSE_DIM + condition_dim + 1, hidden_dim),
        nn.ReLU(),
        nn.Linear(hidden_dim, hidden_dim),
        nn.ReLU(),
        nn.Linear(hidden_dim, NUM_FRAMES * POSE_DIM),
    )
```

输入维度 `240+3+1=244`，由含噪动作、类别、归一化时间构成；网络为 `244→256→256→240`。这里只用一个时间标量，没有正弦时间嵌入、注意力或 U-Net。

##### 去噪机器接收三种材料

```text
含噪动作240项 + 类别3项 + 加噪时间1项 = 244项
                          ↓
                    两层隐藏特征
                          ↓
                     噪声240项
```

像让修图员看到一张带污点的图、图的类别和污染程度，再标出污点。这里一张“图”实际上是整段动作展开的向量。

同样输出 240 项，并不意味着与 PoseMLP 在做同一个任务。网络的学习目标由后面的 loss 指定：NoisePredictor 与真实 noise 比较，PoseMLP 与真实 pose 比较。

#### `NoisePredictor.forward`

原文件：`src/models.py`，第 87 行起。

```python
def forward(self, noisy_pose, condition, time_fraction):
    inputs = torch.cat([noisy_pose, condition, time_fraction.unsqueeze(1)], dim=1)
    return self.network(inputs)
```

`time_fraction` 从 `[B]` 加一维为 `[B,1]`，与 `[B,240]` 的 noisy_pose 和 `[B,3]` 的 condition 沿特征维拼接成 `[B,244]`。最后输出预测噪声 `[B,240]`。

##### 三张表横向装订

B=2 时，noisy_pose 是两行各 240 列，condition 是两行各 3 列，time_fraction 例如 `[0.0,1.0]`，原本只有一个轴。

`time_fraction.unsqueeze(1)` 将它变成 `[[0.0],[1.0]]` 的两行一列。cat 后每个样本的一行就有 244 项，样本之间没有互相串起来。

输出某坐标的 predicted_noise=0.2，表示模型估计该含噪动作在这一噪声维上的值约为 0.2；不能直接说“该关节坐标是 0.2”。采样器要结合噪声计划才能把它用于更新动作。

## 第三章 B：逐个损失解析

损失把“预测哪里不好”变成可求导的标量。`F.mse_loss(a,b)` 默认对所有元素求平方误差的平均值。数值越小表示按该度量越接近，并不等于动作一定符合真实手语语义。

### 导入与文件级定义

```python
"""易读的姿态坐标、骨骼、速度和关键帧损失。"""
import torch.nn.functional as F
```

#### `coordinate_loss`

原文件：`src/losses.py`，第 5 行起。

```python
def coordinate_loss(prediction, target):
    return F.mse_loss(prediction, target)
```

对 `[B,24,5,2]` 全部坐标计算 MSE：`Σ(pred-target)²/(B×24×5×2)`。例如单个坐标误差 0.1，其平方误差是 0.01；其他元素还会参与平均。

##### 先用一个点手算 MSE

```text
预测点：(0.6,0.7)
目标点：(0.5,0.9)
差值：  (0.1,-0.2)
平方：  (0.01,0.04)
平均：  (0.01+0.04)/2 = 0.025
```

平方避免正负误差抵消，也让较大偏差受到更多惩罚。实际把所有样本、所有帧和关节的坐标都纳入平均；不是先对 x、y 求欧氏距离再平均。

`F` 是 torch.nn.functional 的简称，`mse_loss` 是可复用的函数，不是先前创建的训练对象。返回张量里只有一个数，但仍能保留求导关系。

#### `bone_vector_loss`

原文件：`src/losses.py`，第 9 行起。

```python
def bone_vector_loss(prediction, target):
    pred_bones = prediction[:, :, 1:] - prediction[:, :, :-1]
    target_bones = target[:, :, 1:] - target[:, :, :-1]
    return F.mse_loss(pred_bones, target_bones)
```

`[:,:,1:]` 选择后四个关节，`[:,:,:-1]` 选择前四个关节；相减得到四条骨骼向量 `[B,24,4,2]`。比较的是向量，既包含长度又包含方向，并非仅约束骨长。

整条链统一平移时骨骼向量不变，所以骨骼损失不能单独确定绝对位置，这也是仍保留坐标损失的原因。

##### 点都偏了一些，不一定意味着骨骼方向偏了

用一帧两个点举例：

```text
目标：P0=(0,0)，P1=(1,0) → 骨骼向量(1,0)
预测：Q0=(0.1,0.2)，Q1=(1.1,0.2) → 骨骼向量(1,0)
```

坐标误差不为零，但骨骼向量误差为零，因为两点一起平移，连线的方向与长度没变。

若预测改为 Q0=(0,0)、Q1=(0.8,0.2)，向量差为 `(-0.2,0.2)`，该向量两分量的 MSE 为 0.04。

`prediction[:,:,1:]` 与 `prediction[:,:,:-1]` 像分别写出两列“每条骨头的终点”和“每条骨头的起点”。其中 `:-1` 表示取到最后一个元素之前，不是只取最后一个。

#### `velocity_loss`

原文件：`src/losses.py`，第 15 行起。

```python
def velocity_loss(prediction, target):
    pred_velocity = prediction[:, 1:] - prediction[:, :-1]
    target_velocity = target[:, 1:] - target[:, :-1]
    return F.mse_loss(pred_velocity, target_velocity)
```

这里沿时间轴做差，得到 `[B,23,5,2]` 的每帧位移。时间间隔按 1 帧处理，没有除以真实秒数。

比较预测位移与目标位移，鼓励学对运动变化。虽然参数名叫 smooth_weight，但这不是直接把速度压到 0 的平滑惩罚，也没有计算加速度；目标里有快速运动时它会鼓励跟上快速运动。

##### 比较“每一步怎么走”，不只是“站在哪里”

用一个点的 x 坐标、三帧动作手算：

```text
目标位置：[0.0,0.2,0.5] → 位移：[0.2,0.3]
预测位置：[0.0,0.1,0.5] → 位移：[0.1,0.4]
位移差：[-0.1,0.1] → 一维示例MSE=0.01
```

起点和终点相同，中间节奏仍然不同；速度损失会发现这种区别。实际还有 y、其他关节和全部样本，都一起平均。

这里 `[:,1:]` 沿帧轴操作，而骨骼损失 `[:,:,1:]` 沿关节轴操作，多一个冒号就换了比较对象。目标本来挥得快时，这项会鼓励预测跟上，而不是把运动强行压平。

#### `keyframe_loss`

原文件：`src/losses.py`，第 21 行起。

```python
def keyframe_loss(prediction, target, keyframe_mask):
    mask = keyframe_mask.unsqueeze(-1)
    error = (prediction - target).pow(2) * mask
    return error.sum() / mask.sum().clamp_min(1.0) / prediction.shape[2] / 2
```

mask 从 `[B,24,1]` 扩为 `[B,24,1,1]`，广播到坐标误差，只保留三帧。先求误差和，再除已知帧数、关节数、坐标维数，因此是已知坐标的平均平方误差。`clamp_min(1.0)` 防止 mask 全零时除以零。

总目标里已含所有帧的坐标 MSE，这一项又单独强调已知帧。当前每段 3 帧已知：单个关键帧坐标在总目标中的系数为 `1/(B×24×10)+1/(B×3×10)`，是普通坐标的 9 倍。

##### 只批改标出关键帧的页，再按实际坐标数平均

用一段 3 帧、每帧 1 个点的简例，mask 为 `[1,0,1]`。假设逐坐标平方误差如下：

```text
第0帧：[0.01,0.04]  ×1 → 保留
第1帧：[0.25,0.36]  ×0 → 忽略
第2帧：[0.09,0.16]  ×1 → 保留
```

误差和为 0.30，已知帧有 2 个，每帧 1 点×2 坐标，平均误差为 `0.30/(2×1×2)=0.075`。这是对函数的手算示例，mask 不必来自当前固定三帧策略。

`error` 指向筛选后的平方误差表；`error.sum()` 求总扣分，`mask.sum()` 数已知帧（跨所有样本）。由于 mask 本身每帧只有一个开关，还需除关节数和 2，才是每个有效坐标平均。

`clamp_min(1.0)` 像给分母装下限保护；如果一帧也没给，error 全为零，返回零而不是除以零。

## 第四章：扩散模型的训练与采样

先区分：数据集的 24 帧是动作时间；扩散的 50 步是加噪/去噪时间。一次扩散更新会处理整段动作的 240 个坐标，不是生成一帧。

### 导入与文件级定义

```python
"""最小化的 DDPM 教学实现。"""
import torch
```

#### `make_noise_schedule`

原文件：`src/diffusion.py`，第 5 行起。

```python
def make_noise_schedule(steps, device):
    beta = torch.linspace(1e-4, 0.02, steps, device=device)
    alpha = 1.0 - beta
    alpha_bar = torch.cumprod(alpha, dim=0)
    return beta, alpha, alpha_bar
```

`beta` 是每步噪声强度，线性从 0.0001 增到 0.02；`alpha=1-beta` 是每步保留信号的比例；`cumprod` 得到累计保留量 ᾱ。三者形状均为 `[steps]`，并创建在指定设备。

噪声计划没有可训练参数。ᾱ 不是普通求和；多个步骤的信号衰减要连乘。

##### 三张表：每步加多少、每步留多少、累计留多少

为了手算，假设仅 3 步，沿用代码的首尾值：

```text
beta      = [0.0001, 0.01005, 0.02]
alpha     = [0.9999, 0.98995, 0.98]
alpha_bar ≈ [0.9999, 0.989851, 0.970054]
```

alpha_bar[1] 是 alpha[0]×alpha[1]，alpha_bar[2] 再乘 alpha[2]。像连续经过几层透光片，总透光比例取乘积，而不是把比例相加。类比只能帮助理解乘积；实际动作信号系数还要取 sqrt(alpha_bar)。

`beta,alpha,alpha_bar = ...` 左边接三张张量表；在 train.py 中它们整体放在 schedule 元组里，因此 schedule[2] 才是 alpha_bar，不是第 2 步。

默认 50 步在本机计算的末项 alpha_bar 约为 0.602952。增加步数不只是让模型多循环几次：固定 beta 首尾、改变步数时，累计衰减也会改变。

#### `add_noise`

原文件：`src/diffusion.py`，第 12 行起。

```python
def add_noise(clean_pose, noise, time_index, alpha_bar):
    selected = alpha_bar[time_index].unsqueeze(1)
    return selected.sqrt() * clean_pose + (1.0 - selected).sqrt() * noise
```

`time_index:[B]` 为各样本选出不同的 ᾱ，经 unsqueeze 变为 `[B,1]`，可广播到 `[B,240]`。

公式：`x_t = sqrt(ᾱ_t) x_0 + sqrt(1-ᾱ_t) ε`，其中 ε 是标准高斯噪声。这能直接构造任意时间步的含噪动作，训练不必先循环执行前面所有加噪步骤。网络学习恢复 ε，而非直接背诵 x_0。

##### 不是直接 clean + noise，而是按强度配比

假设为了演算，某个样本所选 alpha_bar 恰好是 0.64，某坐标 clean=0.5，抽到 noise=-1：

```text
sqrt(0.64)×0.5 + sqrt(0.36)×(-1)
= 0.8×0.5 - 0.6
= -0.2
```

0.64 是手选数值，不是声称 50 步中恰有这一项。得到负数完全可能，因为含噪坐标不要求在画面范围内。

若 time_index=`[0,49]`，`alpha_bar[time_index]` 会分别为两个样本查表。unsqueeze 后每行一个强度系数，通过广播作用于该样本的全部 240 项；不会给每个坐标另外抽一个时间步，但 noise 的每项都是各自的随机值。

这像制作不同污染程度的练习题：原图已知、污点也由老师生成，所以老师知道应该让学生预测什么。函数本身没有可训练权重，只负责制作输入。

#### `sample_pose`

原文件：`src/diffusion.py`，第 17 行起。

```python
@torch.no_grad()
def sample_pose(model, condition, steps, pose_dim, device):
    beta, alpha, alpha_bar = make_noise_schedule(steps, device)
    pose = torch.randn(condition.shape[0], pose_dim, device=device)
    model.eval()

    for step in reversed(range(steps)):
        time = torch.full(
            (condition.shape[0],), step / max(steps - 1, 1), device=device
        )
        predicted_noise = model(pose, condition, time)
        beta_t = beta[step]
        alpha_t = alpha[step]
        alpha_bar_t = alpha_bar[step]
        pose = pose - beta_t / torch.sqrt(1.0 - alpha_bar_t) * predicted_noise
        pose = pose / torch.sqrt(alpha_t)
        if step > 0:
            pose = pose + torch.sqrt(beta_t) * torch.randn_like(pose)
    return pose
```

1. `@torch.no_grad()` 不建梯度图，`model.eval()` 切换评估模式。
2. 从 `[B,240]` 的标准高斯随机数开始生成。不同初始噪声可产生不同结果。
3. 从 steps-1 倒数到 0，构造与训练一致的归一化时间，预测当前动作中的噪声。
4. 两次赋值合起来实现均值更新：`μ=(x_t-β_t/sqrt(1-ᾱ_t)×εθ)/sqrt(α_t)`。
5. 不是最后一步时，再加 `sqrt(β_t)×z`。这是使用 β_t 作为反向过程方差的简化选择，并非精确后验方差公式。最后一步不再加随机噪声。
6. 返回展平动作，由调用者 reshape。

重要局限：默认只有 50 步且 beta 上限为 0.02，末端 ᾱ 约 0.60，信号系数仍约 0.78，因此训练末端分布未充分接近采样起点的纯高斯噪声。这个教学配置可能生成较差；噪声预测损失下降也不能保证采样质量。理解流程后可研究更长时间表或更合适的计划。

##### 生成阶段没有标准答案可偷看

此函数只收到 model、condition 等设置，没有 target。最初 pose 是随机噪声，像一张完全打乱的动作草稿；每步问网络“你认为这里有哪些噪声”，按公式修正，再继续问。

50 步时 `reversed(range(steps))` 依次产生 49、48、…、0；归一化 time 则依次为 1、48/49、…、0。这不是在倒放动作的 24 帧，每次都更新全部 240 个坐标。

用假想单坐标值演示一次算术：pose=0.5，预测噪声=0.2，beta_t=0.01，alpha_t=0.99，alpha_bar_t=0.64，则均值更新为：

```text
先减噪：0.5 - 0.01/sqrt(0.36)×0.2 ≈ 0.496667
再缩放：0.496667/sqrt(0.99) ≈ 0.499169
```

这些参数是便于演算的假设，不是某一真实时间步的实测值。如果非最后一步，再抽到 z=-0.3，则随机项 `sqrt(0.01)×(-0.3)=-0.03`，该坐标暂变为约 0.469169。

这不是每一步都让某个坐标变小，也不保证每一步到某个固定目标的距离单调下降；过程由网络预测、计划系数和随机项共同决定。最后一步不加新的随机项，但最初噪声与前面步骤仍带来随机性。

`torch.full((B,),数值)` 创建 B 个相同时间值，因为当前采样批次统一走到同一步；训练时每个样本可随机取不同步。`randn_like(pose)` 则生成同形状的新噪声。返回的是采样得到的动作向量，不是网络参数。

## 第五章：把三个进阶实验串起来

### 多条件 multi_condition

数据中的 extra → build_condition 五档量化 → 类别与额外条件拼成 6 维 → PoseMLP → 坐标 MSE。

额外条件让网络能区分左右、体型和水平位置，减少“同输入对应不同答案”的歧义。量化后的尺度/位置仍有信息损失，速度也没有输入，因此无法据此期待每个目标都被精确恢复。这个实验没有继承 bone 或 temporal 的额外损失。

### 多头 multi_head

类别 3 维 → shared 128 维 → 身体头 144 维与手部头 96 维 → 按关节拼接 → 坐标 MSE。

拆分输出有助于理解共享表示与任务分支，但此处没有真实手部细节、独立手部条件或专门损失。只用类别仍然存在平均动作问题；多一个头不会自动补齐缺失条件。

### 关键帧 keyframe

类别 + 三帧真实坐标 + mask → 267 维输入 → KeyframePoseNet → 预测全部 24 帧 → 全序列坐标 MSE + 关键帧 MSE。

训练和预览都会从目标提供三帧。应用时也需要已知关键帧；不能在没有关键帧的情况下照搬这个输入接口。它没有从目标读取其余帧作为输入，但这些帧会作为监督答案参与损失。

七个 experiment 是分别选择的分支，并非自动层层叠加。不要把 multi_head 理解为“扩散 + 多条件 + 多头”的综合系统。



### 用同一个样本把三个实验连起来

假设要预测“指向”，方向向左，且给出了第 0、12、23 帧：

- multi_condition 收到类别和方向等条件，可以知道应该往左，但没看到真实坐标。
- multi_head 只收到类别，虽然有两个输出头，也不会凭空知道这个样本向左；分头不等于增加条件。
- keyframe 收到类别与三帧坐标，可以从已知坐标推断方向、位置和尺度，再补其余帧。

像三位画师：第一位读文字提示，第二位把绘图分工给身体与手部助手，第三位拿到了三页参考图。题目线索不一样，不能只看最终谁更像目标就把优势全部归给网络结构。

### 为什么同样输入可能得到“缩小”的动作？

只看某个坐标，假设同一类别一半样本答案是 0.2，另一半是 0.8，而输入没有方向提示。模型对同一个类别只能给出一个确定值：

```text
若预测0.2，平均平方误差=(0²+0.6²)/2=0.18
若预测0.5，平均平方误差=(0.3²+0.3²)/2=0.09
```

0.5 虽然不是这两种答案中的任意一种，却让 MSE 更小。这是平均化的来源，不代表模型有意生成第三种真实手语。添加条件减少歧义，随机生成则能建模多种可能，但两者都需要正确的训练设计。

#### `draw_pose_sequence`

原文件：`src/visualize.py`，第 11 行起。

```python
def draw_pose_sequence(axis, pose, title):
    pose = np.asarray(pose)
    frames = np.linspace(0, len(pose) - 1, 6, dtype=int)
    colors = plt.cm.viridis(np.linspace(0.15, 0.95, len(frames)))
    for frame, color in zip(frames, colors):
        points = pose[frame]
        for start, end in BONES:
            axis.plot(
                [points[start, 0], points[end, 0]],
                [points[start, 1], points[end, 1]],
                color=color, alpha=0.75, linewidth=2,
            )
        axis.scatter(points[:, 0], points[:, 1], color=[color], s=18)
    axis.set_title(title)
    axis.set_xlim(0, 1)
    axis.set_ylim(1, 0)
    axis.set_aspect("equal")
    axis.grid(True, alpha=0.2)
```

将数据变成 NumPy 数组；在全序列中均匀抽 6 帧，24 帧时索引是 0、4、9、13、18、23。viridis 为各帧分配从早到晚的颜色。

对每帧按 BONES 连接关节，再用散点显示关节。`alpha` 控制透明度，linewidth/s 控制线宽和点大小。设标题、坐标范围和等比例显示，避免骨骼因横纵比例不同看起来变形。`ylim(1,0)` 使 y 轴朝下，贴近图像坐标。这里是多帧叠图，不是动画。

##### 从坐标表到六张叠在一起的剪影

`axis` 是 Matplotlib 子图对象，类似你准备作画的一块画板；`pose` 是动作数字；`title` 是标题字符串。只有 pose 是动作数据，axis 不是张量。

例如某帧第 0 点 `(0.5,0.78)`、第 1 点 `(0.66,0.90)`，画骨骼时传入：

```text
x列表：[0.5,0.66]
y列表：[0.78,0.90]
```

plot 将这两个点连成线。`for start,end in BONES` 依次拿到 `(0,1)`、`(1,2)` 等连接表，scatter 再在点的位置画小圆点。

`colors` 为抽出的六帧各准备一种颜色；`zip(frames,colors)` 一次配对一个帧号和一种颜色。颜色表示时间顺序，不表示分类结果或误差大小。

`set_xlim(0,1)` 像把相机取景框固定在 x 的 0 到 1；超出范围的点可能被裁掉，并不意味着原数据被改成边界值。首节实测指向样本有 x 大于 1 的点，就是可能出现裁切的例子。等比例坐标则让横向 0.1 与纵向 0.1 在图上同样长。

### 4. 用几个问题检查理解

- 为什么一个动作有 240 个数，而不是 24 个类别？因为模型回归所有帧所有点的坐标。
- 为什么需要隐藏层激活？没有非线性时，多层线性变换整体仍是线性变换。
- 验证为什么不更新参数？它检验对训练外样本的表现；参与更新会失去这层意义。
- 骨骼损失能否确定根节点位置？不能，整体平移不改变骨骼向量。
- 关键帧为什么要传 mask？零坐标也可能是真实值，不能仅凭零识别缺失。
- 扩散是否每次预测一帧？不是，它每步预测整段动作向量里的噪声。

### 6. 阅读一行新代码时的四个问题

1. 右边返回的是对象、数组/张量、普通数字，还是一组结果？
2. 左边这个名字之后在哪里被读取？同名变量是否只在本函数局部有效？
3. 若是张量，每根轴各代表什么，元素有没有真的被计算修改？
4. 这行属于制作数据、模型预测、计算损失、更新参数、还是保存结果？

例如 `rng = ...` 属于制作数据的准备，`pose = make_pose(...)` 制作标准答案，`prediction = model(...)` 才是网络预测，`optimizer.step()` 才调整参数。把这几个阶段分开，阅读后续模型通常会容易很多。
